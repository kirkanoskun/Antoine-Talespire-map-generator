# Revue du 14 novembre 2026 et plan d'amélioration

Base examinée : `f5d1fc3` (après la fusion du lot 1). Revue de tout le projet :
moteur, lecture des réponses d'IA, site, mise en ligne, dépendances,
documentation. Demandée par Antoine, avec la création de « fall back ».

## En bref

Le projet est sain. Le moteur ne plante pas, les tests sont nombreux et le site
ne dépend d'aucun serveur. Trois faiblesses ressortaient, et les trois sont
traitées dans cette livraison :

1. **Le moteur était trop strict avec les IA.** Il refusait une carte pour une
   virgule en trop. Il répare maintenant ces erreurs tout seul.
2. **La mise en ligne n'avait pas de filet.** Une version cassée pouvait être
   publiée, et rien n'était prévu pour revenir en arrière.
3. **La version de Go n'était plus maintenue** et traînait 15 failles connues.

## Comment la revue a été faite

- Outils automatiques : `go vet`, `staticcheck`, `govulncheck`, couverture de
  tests, recherche de secrets dans le dépôt.
- Test de robustesse : 44 réponses d'IA abîmées ou hostiles envoyées au moteur
  (nombres à virgule, mots en français, 3 000 zones, comptes absurdes…).
- Test aléatoire (fuzzing) de la nouvelle lecture tolérante : 1,7 million
  d'entrées.
- Lecture du code par zones à risque : entrée des données, serveur, pont entre
  la page et le moteur, workflows de mise en ligne.
- Contrôle du site en ligne : en-têtes, fichiers servis, compression.

## Les « fall back » créés

### 1. Réparer les réponses d'IA au lieu de les refuser

`ir.ParseLenient` lit la réponse, corrige ce qui est bénin, et renvoie la liste
des corrections. La page l'affiche sous la carte : « Le Cartographe a corrigé 3
détails dans la réponse de l'IA ». Une carte déjà correcte n'est pas touchée.

| Erreur de l'IA | Ce que fait le Cartographe |
| --- | --- |
| Nombre à virgule (`20.4`), nombre entre guillemets | Arrondi |
| Champ inventé (`"notes"`, `"rotation"`, `"mood"`) | Ignoré |
| Biome en français ou en majuscules (« Forêt tempérée ») | Compris |
| Relief en français ou synonyme (« Colline », « valley ») | Compris ; inconnu : terrain plat |
| Taille de zone en pourcentage (`60`) ou absente | Convertie ; valeur par défaut |
| Zone ou objet une case hors de la carte | Ramené dans la carte |
| Position écrite `[3, 4]`, « centre », ou absente | Convertie ; centre de la zone |
| « scattered » sans nombre | Un seul objet |
| Densité hors bornes ou nommée « trees » | Bornée ; comprise |
| Sol inconnu (« cobblestone ») | Sol le plus proche du biome ; sinon terrain naturel |
| Objet mal orthographié (« Fountain 01 ») | Compris (`fountain_01`) |
| Bâtiment inconnu | Laissé de côté |
| Chemin entre des zones inexistantes, largeur absurde | Ignoré ; bornée |
| Deux zones du même nom, zone sans nom | Renommée |
| Carte de plus de 200 cases | Réduite à 200, positions mises à l'échelle |
| Commentaires, virgules en trop | Retirés |
| Deux blocs JSON, accolades dans le texte autour | La dernière carte complète est prise |

Restent refusés, avec un message à renvoyer à l'IA, parce que les réparer
reviendrait à deviner la scène : une carte **sans aucune zone**, un **biome
absent ou inconnu** (le message liste maintenant les biomes valides), et un
texte qui n'est **pas du JSON** (guillemets simples, par exemple). Une réponse
de plus de 1 Mio reste refusée aussi : c'est une limite de sécurité. Ce sont
les 3 refus restants du test de robustesse.

### 2. Solutions de repli quand quelque chose casse

- **Moteur du site** : le téléchargement est retenté deux fois. Un moteur qui
  s'arrête en cours de visite est relancé (deux fois au plus) et la demande en
  cours est reposée. En cas d'échec, un bouton « Réessayer » recharge la page
  sans perdre le texte. Un navigateur sans WebAssembly reçoit un message clair.
- **Sol, bâtiment, chemin inconnus** : la carte est dessinée sans eux, et la
  liste des corrections s'ouvre d'elle-même pour le signaler.
- **Objet au bord de la carte** : décalé à l'intérieur plutôt que supprimé.

### 3. Retour arrière du site

- Rien n'est publié sans tous les tests (moteur, WebAssembly, navigateur).
- Après publication, `scripts/check-site.sh` compare le site en ligne au site
  construit, octet pour octet. En cas d'écart, la version précédente est
  remise automatiquement et le workflow reste rouge.
- Trois façons de revenir en arrière, décrites pas à pas dans
  `docs/site-web.md` : depuis Cloudflare (30 secondes), en republiant un commit
  précis depuis GitHub, ou en annulant la pull request fautive.

## Ce qui n'a pas pu être vérifié ici

- **Le retour arrière automatique** (`wrangler rollback`) : la commande et ses
  options ont été vérifiées, mais elle ne peut pas être exécutée sans les
  identifiants Cloudflare. La comparaison avec le site en ligne, elle, a été
  testée sur le vrai site (cas identique et cas différent).
- **Les nouvelles étapes du workflow GitHub** : elles tourneront pour la
  première fois sur la pull request. Les mêmes commandes passent en local.
- **Le rendu en jeu** : Antoine a collé le cimetière et la place du village.
  Les objets sont sur leurs cases et posés au sol, les nénuphars flottent, la
  fontaine occupe bien ses 4 cases. Ces captures ont révélé le miroir nord-sud
  décrit plus haut. Une carte découpée en morceaux reste à essayer.
