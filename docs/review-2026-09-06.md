## Limites restantes

- Deux ajustements simultanés peuvent encore écraser les changements l'un de
  l'autre : l'instantané supprime la course mémoire, pas le conflit fonctionnel.
  Ajouter un numéro de version attendu et une réponse 409 serait l'étape suivante.
- Les sessions restent en mémoire sans expiration ni limite de nombre.
- Le contrôle d'origine est destiné au lancement local direct. Une exposition
  derrière proxy demande une configuration explicite et une authentification.
- Les POI utilisent des aliases vers des accessoires existants. Une description
  de bâtiment ne devient pas une construction complète.
- Le découpage avertit quand une tranche dépasse la limite, mais ne la redécoupe
  pas automatiquement. La validation dans le client TaleSpire reste nécessaire.

## Slabs TalesTavern : intégration proposée

Vérification le 6 septembre 2026 : l'archive distingue Slabs et Boards ; la fiche
[Restaurant, Bathhouse, and Spa](https://talestavern.com/slab/restaurant-bathhouse-and-spa/)
propose `Copy code` et `Display code`. Le
[guide TalesTavern](https://talestavern.com/talespire-guide-to-sharing-copying-using-slabs-and-boards/)
décrit le partage et l'import. Le code brut de ce bâtiment n'a pas été extrait ni
testé avec le décodeur de ce dépôt. Aucune API publique stable n'a été vérifiée.

Architecture recommandée, non implémentée dans cette correction :

1. Importer un code de Slab copié par l'utilisateur, avec titre, auteur et URL.
   Conserver les conditions de réutilisation lorsqu'elles sont fournies ; ne pas
   déduire une permission de redistribution de la seule visibilité publique.
2. Décoder avec limites de taille compressée, taille décompressée et nombre
   d'assets. Refuser proprement les formats incompatibles et les liens Board.
3. Stocker le bâtiment comme prefab identifié, avec dimensions, entrée et
   coordonnées relatives. Ne pas intégrer le base64 aux instructions du modèle.
4. Fournir au modèle uniquement les identifiants validés, dimensions et usages.
   Étendre l'IR avec des placements de prefab et une rotation contrôlée.
5. Réserver l'emprise avant de disperser les arbres et rochers ; aplanir le sol,
   conserver les positions relatives, vérifier limites et collisions, puis encoder.
6. Tester aller-retour du code, placement, rotation et import dans TaleSpire.

Les instructions actuelles signalent désormais la limite : elles ne doivent pas
inventer un bâtiment, une URL ou un code Slab comme identifiant de prop.
